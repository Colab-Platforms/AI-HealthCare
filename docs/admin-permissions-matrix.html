Who can do what: Admin, Take Admin, Super Admin

From the three Take Health admin documents (section 9.3 permission table). Version 1.0, 20 Nov 2026.

Admin

Runs daily work: users, support tickets, report status.

Cannot approve anything

Take Admin

Runs growth: analytics, campaigns, food drafts, management reports.

Cannot approve anything

Super Admin

Controls the platform: approvals, admins, roles, security, AI settings.

1. Quick answer: who can edit or delete

Edit directly (no approval)

  • Admin: only support tickets assigned to them (status, reply).
  • Take Admin: all permitted support tickets.
  • Super Admin: users, regional settings, food database, AI settings, support tickets, system settings. Their own high-risk edits still need a second Super Admin.

Delete

  • Admin: never directly. Can only request a user or food deletion.
  • Take Admin: never directly. Can only request a food or user deletion.
  • Super Admin: can delete after the approval rules. Permanent deletion needs extra confirmation, and a second Super Admin for high-risk items.

Must go through approval

  • Correcting a health profile (height, weight, allergies, goals)
  • Blocking or deleting a user
  • Adding, editing or removing a food item
  • Re-processing or correcting a medical report record
  • Sending a notification or campaign to users
  • Changing AI settings, exporting private data

3. Rules that apply to everyone

1. Nobody can approve their own request.   2. High-risk actions (deleting users, permissions, security, AI settings, deleting foods) need a second, different Super Admin to confirm.   3. If the record changes before approval, the request goes back for a fresh review.   4. A failed execution is shown as Execution failed, never as done.   5. Every view, request, decision and export is saved in the audit log, which cannot be edited or deleted.

4. Where the code is today

The permission table above is the target. In the code, the new approval and analytics APIs (/api/admin/v1/*) follow it and are enforced on the server. The older admin APIs (/api/admin/*) still let any admin or superadmin edit and delete foods, doctors, diet plans, supplements and deficiency rules directly, with no approval. They are not yet moved onto the approval flow, so an Admin today can do more than the table allows. That migration is still to do.
